ARQUITECTURA TÉCNICA (Versión 1.0)
Objetivos

La aplicación deberá cumplir los siguientes requisitos técnicos:

Arquitectura modular.
Separación estricta entre frontend y backend.
API REST preparada para futuras integraciones.
Base de datos PostgreSQL.
Diseño responsive.
Alto rendimiento.
Seguridad desde el diseño.
Escalabilidad horizontal.
Código mantenible.

Mi recomendación: arquitectura basada en dominios

Hay una decisión adicional que considero muy importante. En lugar de organizar el código por "capas" (controllers, services, repositories en carpetas separadas), organizaría el proyecto por dominios funcionales.

Por ejemplo:

clientes/
├── cliente.controller.ts
├── cliente.service.ts
├── cliente.repository.ts
├── dto/
├── entities/
├── validators/
├── tests/
└── cliente.module.ts

Y lo mismo para suscripciones, finanzas, productos, etc.

Esta organización hace que cada módulo sea casi independiente, facilita el mantenimiento y permite extraer funcionalidades a microservicios en el futuro si el proyecto creciera mucho.
